# Character production

Use for every character step and correction. Read references/guided-workflow.md and only relevant references/model-craft topics. Accepted source artwork/model versions are authoritative. Deliver Unity assets; no VRM or mandatory toon shader.

1. Read current project/workflow state through MCP: active step, revision, selected inputs, hashes and blockers. A resumed conversation does not replace persisted state. Inspect the next actionable prerequisite, including exact slot/candidate IDs; a pending return is not an adopted assembly input.
2. Read newly selected/changed Skills. Reuse unchanged loaded context; reread after compaction when necessary. Acknowledge context only after processing the request.
3. State the local goal, target regions, protected properties, comparison views/poses and completion checks. Carry forward established decisions.
4. Checkpoint before any destructive operation. Use operation-owned copies; never overwrite source art, accepted models or the only input.
5. New image targets are only a whole head WITH all hair and a clothed body. Later segmentation/texture grouping does not create a separate generation mode.
6. Tripo mesh/segmentation/UV/retexture/rig work is manual user work. Prepare real files/settings and clear return instructions. Do not automate its website/API.
7. Run audited scripts with auto-execution disabled, bounded inputs, one thread and new outputs. Never execute embedded source scripts/drivers, install tools or change shaders silently.
8. Register artifacts, dependencies, operations and versions, then submit to precise slots. A prompt, registered file or self-written success JSON is not independent validation.
9. Check actual saved output bytes and reopen/reimport. A missing check blocks completion. Matching vertex counts do not prove correspondence.
10. Report file existence, successful decoding, geometry correspondence, material readiness, visual quality and target-engine verification separately. No single green file check proves all of them. Human Accept/Continue controls adoption and advance.

MCP integration: read `guided_workflow_get`; attach source art with `guided_source_add`. Register actual files with `asset_register`, then submit pending typed results through `guided_output_submit`. Use `guided_correction_submit` for versioned changes to an adopted target. Use `guided_handoff_prepare` for managed manual handoff packages, `guided_surface_run` for allowlisted component/group/surface operations, and `guided_validate` for independent checks. These tools never replace human adoption or Continue. If a tool is unavailable, report the missing capability and leave the step blocked.

Tools: scripts/mesh_quality_tools.py provides audit, snapshot, compare and copy-only normalization for named meshes. Its unverified list is mandatory context: it does NOT certify complete rig preservation, appearance or Unity behavior.
scripts/guided_surface_tools.py inventories components, prepares declared texture groups/guides, exports a mesh-only rig baseline and restores materials through verified face correspondence.
Existing fingerprint_scene.py, uv_surface_tools.py, join_assembly.py, validate_workflow.py and export_candidate.py remain authoritative for their stronger independent invariants.

Deliver actual files, input/output hashes, modifications, preserved properties, executed checks, limits and next action. Corrections create new candidates, never overwrite accepted bytes.

## Recoverable production

- A correction names the exact slot, rejected/current candidate, artifact ID/hash, part/group/view, user note, protected slots and actual input files. Never replace that context with a generic generation request. Keep defective images as diagnostics, not generation inputs. Diagnose the defect and revise the prompt and conditioning strategy. Every color-view correction creates a fresh candidate from original color artwork; at most one clean current same-part non-target view may supplement it as an optional anchor, with truthful pending/accepted status and hashes. Do not edit or regenerate from a failed target copy. For depth corrections, use the exact current paired color view/hash as primary input and original artwork only as secondary identity evidence. Record service refusal/failure honestly; no file means no successful generation. Continue every requested view in this stage until each is ready for human review or a genuine generation blocker occurs; do not defer unresolved view defects to a later texture stage. Leave genuinely blocked work resumable.
- For color-view generation, always start a fresh candidate from original source artwork; a clean current non-target view may be an optional visual anchor. Reserve current-candidate editing for explicitly scoped geometry, material, or texture repair where the declared correction mode permits it. Pass the actual managed image file, not merely a sentence naming it. Versions belong to individual views; an accepted set can contain front v2 and sides v1 without renaming old bytes.
- A changed color makes only derivatives of its old hash stale. Preserve selected files, candidate history and unaffected views. New paired color/depth inputs capture exact parent hashes. Stale does not mean deleted; restore a historical candidate as a new pending version and let a human adopt it.
- Inspect handoff composition before asking the user to leave Atelier. Give actual existing paths, roles and hashes, an export folder and clear return slots. For texture generation each group contains exactly its own model and its two accepted front/back texture-reference PNGs. Guides, depth maps and general body references are not paint replacements and do not belong in that upload bundle.
- Import into an empty Blender scene and export only explicitly imported mesh/armature objects. Reopen the final output in another empty scene and verify actual geometry/material/rig contents, bounds and hashes. No startup cube, camera or light. Exit code zero alone is not success.
- Resolve stale FBX texture paths only against uniquely matching registered dependencies. Support FBM structure without reading arbitrary external files. A self-contained preview must really decode its images and assign its PBR channels/UVs; base color alone is not complete PBR. Preserve source files and surface correspondence baselines.
- At material return, import/review/adopt every required group first. Explain the precise missing group or acceptance prerequisite. Then assemble against the accepted baseline, verify surface mapping and ask for human assembly adoption. Complete the separate head-to-body fitting substep: transform all declared head-source groups together, leave the body fixed, save/reopen a new candidate, and have the human inspect and confirm the exact placement. A geometry mapping report does not prove that the head is on the neck. Stage11 rig-source production requires the confirmed fitted model, never the original overlapped assembly. A new source or fit candidate requires renewed confirmation. Never skip the human gate or mark step10 finished because all archives exist.
- Explain every stage using its purpose, required inputs, immediate action, expected outputs and review criteria in the app language. An empty output slot is not an instruction. Distinguish manual Tripo work, local automation and human review; keep failure/recovery instructions visible until resolved or dismissed.
- Surface matching uses declared group identity and exhaustive uniquely directed face correspondence. Near-coincident vertex candidates can be disambiguated by faces; do not mistake a point-only KD-tree ambiguity for proof of altered geometry. Record the fixed numerical tolerance, alignment, actual residuals and full face coverage. Never expand tolerances repeatedly, choose arbitrary nearest matches or skip missing/duplicate/reversed faces to manufacture a passing assembly. Preserve failure reports and original accepted files.

## Production recovery tools

Use `guided_next_actions_get` to identify the nearest actionable prerequisite and its responsible human/agent, rather than inferring the next action from the first visible output slot. Inspect `guided_handoff_inspect` before preparing an external upload; `guided_handoff_export_directory` provides a verified folder alternative to ZIP. Present actual paths and roles to the user.

Use `guided_candidates_list` and `guided_candidate_restore` for historical/rejected/stale candidates; restoration creates a new pending review version. Use `guided_output_batch_submit` when coordinated color/depth outputs must be submitted together. Read the live tool schema and current revision before any mutation. Do not submit partially matching pairs or retry with a different payload under the same key.

Use `guided_head_fit_run` at Stage10 to produce a placement candidate with explicit world translation, XYZ rotation in degrees and positive uniform scale relative to the accepted textured assembly. The shared pivot is the head mesh bounds centre. Check the exact registered group provenance first. `fit_head.py` preserves local mesh/UV/normal/material/weight/animation data, verifies head-group and untouched body transforms, then reopens the saved output. Its report explicitly leaves anatomicalFitVerified false: only the human confirms placement. Do not submit a human decision through MCP or bypass the fit gate when resuming an older Stage11 workflow.

For missing previews, inspect `guided_asset_preview_status`, then use `guided_asset_preview_retry` and `guided_material_audit` to distinguish registered dependency resolution, image decoding, UVs and assigned channels. Retry is not human adoption. `guided_session_binding_get`, verified `guided_session_binding_repair` and `mcp_diagnostics_get` distinguish app/server readiness from the current client's actual tools. An unknown client state is not a connected/verified state; never force a mismatching character/session association or expose credentials. If a capability is unavailable, report it explicitly and retain the resumable request.

## Embedded session and independent corrections

Use atelier-model-workbench when working from the persistent Codex terminal or the model-workbench tab. Read actual ui_get_context and model_workbench_get_context, navigate through acknowledged tools, and keep the bound character session. The inspected stage is not necessarily the persisted stage. Checkpoint copied sources and declare target objects before edits; trusted workbench_audit.py checks the stated object/purpose preservation policy. Local geometry additions or repair use atelier-mesh-repair; materials/paint use atelier-texture-repair. Workbench versions and production adoption are separate. Never reuse old correspondence/baseline proofs after changed topology, UVs or placement, and never use navigation to complete a human production gate.

## Agent-defined groups

Read `references/agent-defined-groups.md` for component inspection, arbitrary named logical groups, complete assignments and trusted repartition recovery at stages 8–10. Group names/types are not a fixed accessory list. Keep one logical object per group, including its related components, and generate its own mesh guides and front/back paint references. Base exclusions on the actual selected mesh; never delete a present belt/detail from the image to conceal a grouping mistake.
