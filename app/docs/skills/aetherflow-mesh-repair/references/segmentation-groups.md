# Repair semantic group boundaries before texturing

## Diagnose first

Read current workflow, accepted segmented source hashes, actual component inventory, source artwork and accepted color views. Keep all authored material zones, small hair pieces, jewelry and skin/clothing boundaries visible during inspection. Position, size, object name or waist height alone never establishes semantic ownership. Tiny frontal locks and disconnected hair flecks still belong to hair; facial skin belongs to head. Necklaces and bands present in a torso mesh must remain in its painted projection unless deliberately separated. Abdomen/navel/side skin belongs with the observed torso, not with a nearby belt or automatically with legs. Keep genuine outfit/leg boundaries from the actual character; do not impose a universal waist plane or accessory taxonomy.

Use `guided_components_list` and `guided_surface_run(mode=inspect-components)` for uncertain whole components. Inspect new `partitionReview.images` against its color legend after every prepare/repartition operation. These are actual front/back group-colored mesh overviews, separated by source frame, not a semantic pass certificate. Older projects may not have these images: inspect their existing stage8 group viewer or render the saved group baseline on a copy in Blender. Do not repartition unchanged geometry solely to obtain screenshots. Inspect each group in isolation and in context; use Blender for side/oblique closeups when overlap hides a boundary. Keep a component-to-group decision ledger with uncertain cases and evidence. Resolve wrong membership before generating paint. Reinspect the saved corrected result, not just the proposed assignments. Geometry coverage proves nothing about whether a component is hair, skin, cloth or jewelry.

## K0a — whole component transfer

For separate components, use complete exactly-once assignments with existing or agent-defined named groups and revision-bound `repartition-groups`. Compound logical objects may contain several component IDs. The tool preserves the original bytes and checks actual surfaces. Do not ask the user to manually assign hundreds of pieces.

## K0b — a desired region is connected to another part

Do not stop merely because the whole-component tool cannot split it. Use `scripts/repair_group_boundary.py` on a staged copy of the accepted raw segmented source, before rigging. This route separates existing faces along existing edges; it never guesses a plane, adds a cap, deletes unwanted skin, remeshes, changes the shape or reconstructs anatomy. A boundary that needs new edges or shape repair requires the separate local reconstruction methods and a new surface proof.

1. Pin the exact managed source hash and mesh object. Use `mode=catalog`, `offset`, `limit` (up to 200) to read bounded original face IDs, material identity and world corners. Inspect the source in Blender and determine explicit face IDs from geometry/material continuity. Never infer ownership from Y/Z height alone.
2. Run `mode=inspect` with those `faceIndices` and a fresh `outputDirectory`. Inspect the red selected region against the gray retained surface in front/back/left/right/top/bottom/oblique context renders, plus normal-aligned isolated closeups and Blender side/oblique views as needed. The output includes a `selectionHash`; refine the selection until it includes every intended face and no healthy neighboring layer. Do not call the numerical inspection a semantic approval.
3. Run `mode=split` with the same pinned input/object/face IDs, the exact `expectedSelectionHash` from that inspection and a new directory. A different selection or source hash is rejected. The script checkpoints source bytes, makes two objects sharing the original seam positions, copies UVs/material assignments/corner normals/attributes, saves and reopens a new `corrected-segments.blend`, and proves every original surface face occurs exactly once with unchanged world corners. Static pre-rig sources only; modifiers, shape keys, rigs, constraints, animation and dependent child objects require their own explicit preservation route.
4. Inspect the reopened output and seam from front/back/side, including hidden surfaces. The seam is deliberately separated; no cap or welding is implied. Do not claim removal of a geometric protrusion when only ownership was changed. Preserve original source and reports.
5. Register the corrected native Blender file under this character. Submit a new correction to the exact accepted `segmented-head` or `segmented-body` slot with `guided_correction_submit`; attach the inspection/split report and explain face selection and intended membership. A native Blender correction is supported by the managed model path. Do not replace object-store bytes, write the application database or overwrite reserved group slots by hand. Human adoption of this new segmentation is required.
6. After human acceptance and normal Continue to stage 8, inventory the new accepted segmented pair, then repartition using its real new component IDs. Reuse the unchanged partner source. Rebuild group meshes/guides and geometry-dependent handoffs/returns; keep the user's approvals of existing color images. Compare those images to current guides and regenerate only actual mismatches. A pending restoration of identical previously accepted image bytes is not a reason to request repeated human approval after partition-only invalidation.

Example config keys (derive every value from the current model, never reuse historical indices): `mode`, `input`, `expectedHash`, `object`, `faceIndices`, `outputDirectory`, and for split `expectedSelectionHash`. Run with Blender background, factory startup, disabled autoexec and one thread. Read actual `report.json`, managed hashes and the saved output. Tool success establishes preservation, not semantic correctness; human adoption remains explicit.

## Stage 9 — preserve every visible material detail

Create a positive per-group inventory before image generation: visible components, authored skin/cloth/hair/metal/glass zones, jewelry, bands, fasteners, patterns and intentional transparent elements. Attach the actual guide plus original and accepted color views. A gray mesh bulge does not mean skin: consult design and material boundaries. State required details positively in the prompt; exclusions must come from this group's actual contents, never from the generic group label. A necklace on the torso must not become skin-colored paint. A belt must not acquire abdomen skin because an earlier wrong segmentation contained it.

Compare each decodable draft with its guide and inventory, front and back: outer contour, every disconnected piece, interior openings, coverage/occlusion, accessories, material-zone placement, scale and baseline. Legitimate lace holes and transparent materials are not missing coverage. A reference covering only roughly two thirds of an opaque mesh silhouette is not ready; diagnose missing content or projection/scale mismatch and continue correction from the original guide and clean color anchors. Publish readable drafts for visibility, but do not finish merely because they were submitted as pending. Continue every unresolved requested result until ready or a genuine provider/tool/quota blocker exists, preserving a clear resumable task. Image generation cannot fix wrong mesh membership: repair the partition first.
