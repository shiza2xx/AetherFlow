# Asset AI depth maps

Use the same visual representation and technical tolerances as AetherFlow Characters. Asset ownership and role mapping remain asset-specific: use the exact current accepted color view and itemId, never a character slot.

1. Build an ordered TODO from the accepted catalog and current slots. For modules, finish each required front and side depth pair before moving to the next. For shared props, generate only `depth:front` from its exact accepted color front, even if the catalog also has a side color view. Foliage has no depth. Shared geometry sheets select each prop’s accepted front map when AI depth is enabled and its accepted color front otherwise; do not generate `depth:sheet`.
2. Open the paired color view and `depth-style-example.png`. Attach BOTH to imagegen. The color controls geometry, silhouette, framing and orientation; the unrelated four-view example controls only smooth near-light/far-dark depth on black. Do not copy its character, ornaments, anatomy or four-panel layout. Deliver one standalone full-size view.
3. Remove painted texture, lighting and highlights through generative volume reconstruction. A color-to-grayscale filter is not depth reconstruction. For a substantial volume/texture error, revise the prompt from the paired color and style reference; do not condition on failed depth images.
4. Validate the actual PNG under the shared character contract: opaque alpha >=250, <=8 MiB, <=4096 px per dimension; each border and corner RGB channel <=8/255 inclusive. Near-black (1,1,1) and (0,1,0) pass. Mean RGB channel spread <=2 across the whole image AND foreground, maximum <=16, with at most 0.1% of all pixels having spread >4. Do not demand literal R=G=B or exact-zero background. These checks do not certify semantic volume.
5. Preserve original output bytes. Do not paint over borders or desaturate outputs to disguise semantic defects. No postprocessing is needed solely to remove allowed encoding noise. Submit the best technically usable original candidate with specific visual warnings, not every intermediate attempt. Register under the real item, submit to its exact depth:front or depth:side role, then read the exact slot back. Shared-prop depth is per item and front only. The user alone accepts it.
6. Reuse inspected suitable prior results and preserve their history. If a file genuinely fails validation, report that file's reason and continue other independent TODO pairs. Stop the entire batch only after available work is exhausted or an actual global tool/quota interruption. Failure of one or two views does not prove failure for the remaining items.

## Two-image prompt pattern

Image 1 is the exact accepted {view} color view of {asset}. Image 2 is an unrelated four-view AI-depth style sheet. Create ONE standalone {view} image with image 1's full silhouette, shape, thickness, openings, scale and framing. Reconstruct volume using image 2's continuous neutral gray volumes on black: nearer surfaces lighter, recesses and occluded layers darker. Remove painted texture, shadows and gloss while retaining real structural relief. Do not copy the example's character or layout. This is visual AI depth, not a calibrated sensor map or clay render. Preserve the generator's original PNG; small near-neutral RGB encoding noise is supported by the app.
