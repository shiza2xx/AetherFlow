# Images and source fidelity

## Shared generation contract

Read the original color art, accepted catalog and current job-wide depth choice. A request to generate the entire list covers all masters and their required views. Before generating, emit an explicit TODO for every master in catalog order, with its real name, item ID, each required role and that role's saved status. Do not invent IDs or omit a later page. Process one master at a time, completing front then side for standard items before advancing; use foliage roles front, back, side, top. Follow accepted catalog views: walls/windows require side; roof side is included only when the accepted catalog lists it. A TODO status is a work order, not proof of a completed image. Generate independent, correctly framed views using each item's actual role. Match geometry, proportions, palette, material, ornament, lighting, scale, and margins across the set. Do not inherit wind-blown volume or moving thin elements as a permanent mesh shape. Never remove a real ornament because a generic prompt called it an accessory.

The original color artwork defines the artistic style and rendering treatment for every view and every candidate, including alternatives and corrections. Match its brushwork, shapes, texture frequency, colors and level of detail instead of beautifying, polishing, making it more realistic, replacing it with generic 3D or otherwise changing the art direction. This is style fidelity, not a mandate to flatten texture or remove intentional detail. Multiple attempts are allowed; compare them privately against the original and the other selected views of the same asset, without generating an over-polished version as an assumed improvement. For a concrete correctable defect, revise the prompt or conditioning using the registered original as the primary reference and at most one clean view of the same asset for orientation; do not edit repeatedly through previous failed outputs. Submit only the best matching version for each role with truthful warnings and keep user acceptance separate.

For a crowded environment concept, provide both the full original and a deterministic crop of the selected structure or detail. The full image establishes style and context; the crop establishes the actual object. Before generation, describe the visible structural evidence: beam layout, window subdivision, frame shape, surface finish, and attachments. Do not replace it with a generic version of the same architectural style or invent symmetry. Explicitly mark any hidden construction as an inference for catalog review.

Explicitly distinguish structural geometry from painted detail. Preserve the intended style without noisy highlights, microgeometry, new objects, baked cast shadows, or clipped edges. Simplification must target the named geometry, not erase surface texture or change the entire art style.

For corrections, update the prompt and start from the original source plus at most a deliberate clean accepted view as a consistency guide. Do not repeatedly edit the previous failed generation into a degraded chain. Verify what was actually attached to image generation.

## Modules

- Walls, wall variants and standalone windows: create one strict orthographic front elevation AND a separate strict 90-degree side profile for each master. Keep identical height, thickness, openings, and shared scale. The side view must remain narrow when appropriate, not become another facade or fill the canvas by stretching. When AI depth is enabled, prepare the matching `depth:front` and `depth:side` from their respective accepted color views.
- Roof: preserve the source-backed roof type, outline, pitch, rise, ridge, eaves, overhang, thickness, tile or shingle courses, spacing, direction, color, and material. When the accepted catalog lists a side for a tiled or pitched roof, prepare a separate strict orthographic side profile exactly 90 degrees from front, at the same scale and height, so the real pitch and depth remain clear. Do not add a side that is absent from the accepted catalog. The listed side must be a true profile, not a second facade, perspective, or three-quarter view; never stretch or flatten it to fill the canvas. Inspect every role impartially against the original and report observed defects separately from uncertain hidden details. If a view has the wrong angle or a visible source-backed geometry/material mismatch, revise its conditioning and retry from the registered original; do not impose an arbitrary low attempt cap while meaningful corrections remain. Do not claim image-generation reliability or guaranteed results, and do not use paid external generation.
- Other modules and individual props: use one strict front view, plus a separate strict 90-degree side view where it is needed. Each role contains one object and one view, never a collage, perspective view, or front/side/back montage. Foliage's four separate views and the explicitly composed multi-object prop sheet remain distinct workflow exceptions.

Use the approved catalog to establish each component's boundaries before creating its reference. Generate a continuous, uncut wall section preserving its material and texture; windows and doors are separate objects, so do not add either them or their openings to a new wall image. When matching sections use the same material, texture and construction, reuse one wall master rather than creating a wall variant for a window or door. Independently catalogued beams or framing also belong in their own references; preserve their appearance and planned placement in the eventual assembly. The user cuts required openings manually. Existing approved references remain intact; propose any replacement or regrouping for human review. Do not depict the complete building as one wall module; use the complete source only for design and placement context. If the reference does not reveal a hidden part or surface, flag that specific inference rather than inventing authoritative details.

For standalone windows and wall sections that include windows, render the glass panes as a simple, even base glass color taken from the original palette. Do not depict a room, scenery, sky or other background through the panes, or add reflections, glare or specular highlights. Preserve the original frame, mullions, window shape, proportions, colors and artistic style. This instruction concerns the appearance of glass inside the window, not the external background of the generated image or a blanket rule about alpha/transparency or final PBR material settings. Apply it only to actual window panes, not other materials or unrelated assets.

Inspect texture frequency separately from geometry: rough plaster, deep wood grooves, exaggerated bevels, and extra studs can turn painted surface variation into unwanted geometry. Preserve the reference's actual finish rather than increasing detail for its own sake.

Image generation may ignore exact pixel framing even when the views depict compatible geometry. Validate silhouette bounds and shared landmarks after generation. Where only framing differs, normalize onto a common canvas using one uniform scale and translation per image, retaining original files and the transformation manifest. Never widen a side view or independently warp height/width to force agreement. If the underlying shape or landmark relationship differs, regenerate from the original and the clean canonical view instead of hiding the mismatch with resampling. True alpha simplifies silhouette measurement; keep deliberate translucent/glass design distinct from background alpha.

For each actual generated file, open and visually inspect it before registering or submitting, as in the character-view workflow. Verify one requested object and one requested view, strict front or 90-degree profile, complete framing and visible-source fidelity in silhouette, geometry, proportions, materials, ornament, palette and style. A collage or materially wrong view is not a valid role: diagnose it, adjust the prompt or conditioning and retry from the registered original, not a chain of failed outputs. Continue unfinished roles without an arbitrary retry cap while meaningful corrections remain; preserve previous results and report any genuine blocker. A correct single view with usable framing may have imperfect details: compare usable attempts privately, then submit only the best draft to the exact slot with specific truthful quality warnings, without presenting it as accepted or complete. Do not block the whole batch over uncertain, hidden or tiny details that the source cannot establish; mark those as approximate, avoid inventing certainty and show the user the best usable draft. Read submissions back. A byte/decode check cannot prove the angle or composition; human review remains separate and no agent may accept the candidate on the user's behalf.

When resuming, inspect the actual pending candidates in the requested slots against these same criteria before treating a role as covered. A pending count or successfully decoded file does not establish suitability. If a pending image is a collage or wrong view, leave the prior candidate in history and generate a corrected candidate from the original; do not accept or delete the prior one. If a pending image cannot be opened for inspection, report that role's real blocker rather than assuming it is suitable. Preserve current accepted outputs and do not generate duplicates of visually suitable pending candidates.

## Shared prop sheets

Create and accept a clean standalone color front for every unique prop. When AI depth is enabled, also create and accept that item’s matching depth:front from the exact color front. Then compose one deterministic geometry sheet in catalog order, selecting depth:front for enabled items and color image:front otherwise. Keep silhouettes separated and full, with no labels, frames, or overlaps. All-color sheets use a neutral canvas. If any depth tile is present, the canvas, outer padding and gaps are black; color tiles keep a neutral tile background and retain their accepted source pixels. The manifest and artifact dependencies record each tile’s item ID, source artifact, exact role, source type, source hash, paired color hash when relevant, rectangle, scale, and background semantics. This single sheet is the geometry-generation input; do not create a second depth:sheet or convert an accepted color sheet into fake depth. Keep original standalone images as the preferred texturing sources.

Use the original standalone full-quality image for a shared-prop texturing handoff only after its model has been partitioned from the current accepted shared model and accepted in its own slot. A reduced sheet crop is only a fallback with a recorded mapping. Inspect that thin parts and separate props survive the sheet scale. Individual module models already include their Tripo textures; keep their accepted model and texture dependencies for downstream processing without requesting a material-slot reimport.

## Optional AI depth maps

Read `depth-generation.md` and attach `depth-style-example.png` plus the exact paired accepted color. Use the shared character technical tolerance; (1,1,1) and (0,1,0) backgrounds pass, and tiny channel differences alone are not failures. Continue every independent depth TODO pair after a local failure.

Generate standalone depth images only for applicable object views when the job-wide depth option is enabled. A shared geometry sheet selects each depth-enabled prop's accepted `depth:front` and each other prop's accepted `image:front`, so one sheet may contain both depth and color tiles. Keep color images unchanged for materials and texturing. Never create `depth:sheet` or convert an accepted color sheet into synthetic depth. The depth generation must reconstruct view-relative depth as smooth gray volume on black, preserve silhouette and overlap order, and remove painted texture/light patterns. It is not a grayscale filter, clay render, or automatic depth estimator substituted without consent.

Use the matching color image as the main geometric source and keep all required views consistent. Validate decoding, background, silhouette, scale, and absence of baked lighting. A quality warning remains a visible candidate; it does not justify hiding the image from the user. Never apply depth conversion to final foliage-card textures.

## Foliage images

Generate four matched views per leaf-and-twig clump: front, back, side, and top. These are additional image-generation outputs, not a user's missing manual input. They depict the same plant species, palette, leaf size, branch structure, and clump density. Use true alpha, not a rendered checkerboard. Preserve slender twigs without a rectangular matte, white fringe, or opaque empty areas.

## Slot submission and recovery

Register the single selected decoded image per item and role and submit it to the exact role. Submit selected results together when supported, then read back the actual candidates. Reuse accepted current images, keep the best usable draft visible with warnings, and resume missing work after interruptions. Preserve previously submitted history. Store warnings separately from structural validity. Do not claim acceptance or completion because an asset registration succeeded.

For a whole-list generation request, call the available image-generation tool in the current run rather than returning a proposed prompt. After each successful submission, read back the slot, update the TODO from saved state, and immediately continue with the next actionable role. Do not stop a normal run after one image while any independent color TODO remains actionable. If one role has a real blocker, record its precise cause and continue other actionable roles. Resume by rebuilding the ordered TODO from current persisted candidates so valid results are skipped and the first unresolved role is next. Verify and use the original registered source for each independent view. Save the returned image bytes or actual output file unchanged to a new workspace file, register it under the owning item, submit its artifact to the precise role using the current revision, and read that slot back. Never fabricate a file path or say a candidate was submitted if persistence or read-back failed. Produce all independent color candidates before waiting for review; matching depth maps, shared sheets and foliage atlases wait only for their actual accepted inputs. If image generation, output persistence or submission is unavailable, preserve completed work and report the specific blocker and remaining roles.

If a generation refuses content, do not infer that all future work with the source is prohibited. Assess the actual request and reference. A materially clarified neutral technical request may be appropriate for otherwise allowed content; do not create retries intended to defeat a safety refusal. Preserve intentional translucent materials such as glass or lace when present; do not apply an unrelated blanket ban on transparency. Offer a non-generative source crop, manual adjustment, or a clearly described alternative when generation cannot proceed.
